## 3. Step 2 — recover the cameras and 3D points

Suggested time: 55 seconds.

- Find the same background details in several images.
- Estimate camera poses and triangulate 3D points.

### Speaker notes

The reconstruction needs the position and orientation of each camera, as well as its projection parameters. If these are not supplied, COLMAP estimates them from matching details in the static background. It estimates camera poses and triangulates sparse 3D points, then refines them together. Reprojection checks compare predicted pixels with observed pixels. This applies the course topics of coordinate transformations and perspective. For the kitchen dataset, calibrated cameras are supplied; for True Skate, I estimate them.

## 4. From a 3D point to an image pixel

Suggested time: 45 seconds.

- Transform the point into the camera coordinate system.
- Divide by depth and apply the camera intrinsics.
- Check visibility before using the projected point.

### Speaker notes

The camera pose transforms a world point into camera coordinates. Perspective projection divides its horizontal and vertical coordinates by depth, then applies the focal length and image center. The function project performs this calculation and returns depth as well as pixels. Visibility must be checked separately. In our project, a near-plane mismatch initially removed board seeds. The function require_board_visibility now rejects unsafe initial seeds. This connects coordinate transformations, perspective and clipping from the course.

## 5. What is a 3D Gaussian?

Suggested time: 60 seconds.

- A soft 3D ellipsoid with a center, size and orientation.
- Opacity controls its contribution; appearance controls color.
- Many overlapping elements represent the scene.

### Speaker notes

A three-dimensional Gaussian is a soft ellipsoid, with influence strongest near its center and decreasing away from it. Its parameters describe its position, size along several axes, orientation, opacity and appearance. The scene is represented by many overlapping elements. Their two-dimensional projected footprints look like soft ellipses; the drawing here is schematic. GaussianModel.create_from_pcd initializes these elements from a point cloud. The scene starts as an approximation: a seed is not necessarily an accurate point on the board surface. Density control can split elements to represent more detail.

## 6. How do Gaussians produce and learn an image?

Suggested time: 65 seconds.

- Project the elements and combine their contributions by depth and opacity.
- Compare the rendered image with the recorded target.
- Use gradients to update scene parameters, then repeat.

### Speaker notes

For a chosen camera, the renderer projects the Gaussians into the image and combines their contributions in depth order using opacity. This produces pixels. Rendering alone does not improve the model. During training, the rendered image is compared with a recorded target. The difference becomes a loss. PyTorch computes gradients through the renderer, and the optimizer changes the scene parameters to reduce that loss. The scene_reconstruction function manages this training loop and calls render. We repeat the process across views and times. This explains how a point-cloud initialization becomes an image-matching scene representation.

## 7. Step 4 — model motion and check the result

Suggested time: 55 seconds.

- 4DGaussians predicts how the reference scene changes with time.
- Dynamic 3D Gaussians fits successive states with motion constraints.
- Render the scene and compare it with a reserved camera view.

### Speaker notes

Four-D Gaussians uses a reference scene and a network that predicts changes from time. Its forward_dynamic function predicts deformed Gaussian parameters. Dynamic Three-D Gaussians instead fits successive scene states with local motion constraints; our train adapter runs that sequence using the authors' functions. Both methods receive calibrated camera poses. This is different from training separate static reconstructions and playing them in sequence. A time-varying render is useful, but it does not automatically prove that a physical point or board rotation is tracked correctly.

### Speaker notes

We have already generated, inspected and used foreground masks in training. This was a training-fit improvement, not reconstruction success. Later static and temporal trials used masks across multiple views, and the latest comparison has 110 masked training images. The remaining task is to refine existing masks, verify timing and surface coverage, and validate board motion.
